# Persistent archive, restore, and guest-session lifecycle controls

This change adds soft-delete archive state for subjects and reviewers, an archived-items page, and owner-gated restore endpoints while preserving manually archived reviewers through `archived_by_subject`. It also replaces the guest New Session confirmation with a custom Guest ID modal and attempts to purge the signed-cookie identity's persistent data before rotating the cookie; Disconnect Session rotates only the current device identity. Backend-specific gaps remain around public-link authorization, destructive-state visibility, and purge completeness. **Watch for:** **High — confirmed** Neon direct quiz links no longer enforce revocation or expiry; **High — confirmed** subject archive/reset flows leave per-quiz Next data-cache entries valid; **High — confirmed** Supabase subject cascades are not atomic; **Medium — confirmed** Supabase purge leaves collaborator-link identity metadata behind.

**Verdict**: NEEDS_CHANGES

## High-level view

Archive state is modeled independently on subjects and quizzes, with `archived_by_subject` distinguishing a subject cascade from a reviewer that a user archived directly. **High — confirmed:** the Supabase adapter performs subject and child-reviewer updates as separate requests, so a partial failure can split their states even though the Neon CTE is atomic.

The active/public filters were added across repository reads and public subject paths, and public share tags are invalidated on archive/restore. **High — confirmed:** the Neon direct-reviewer share query drops the existing revoked/expired predicates, while **High — confirmed** per-reviewer Next data-cache entries use a tag that subject archive and guest purge routes never invalidate.

New Session derives the purge target from the verified HttpOnly cookie, deletes quizzes/subjects and session data, clears pairing tickets, and rotates the cookie only after those operations. Disconnect Session rotates this device without deleting the shared identity, preserving reconnection; **Medium — confirmed:** the Supabase purge still leaves collaborator-link identity fields, and independent cleanup steps can fail after earlier deletion has committed.

<summary>Details</summary>

## Neon direct-share predicate reopens revoked or expired quizzes

**High — confirmed.** In `packages/core/src/repositories/NeonQuizRepository.ts:1006-1014`, the new archive checks sit alongside `COALESCE(q.is_public, TRUE) = TRUE`, but the prior `q.share_revoked_at IS NULL` and `(q.share_expires_at IS NULL OR q.share_expires_at > now())` conditions were removed. The public sets API and the review/practice pages call this method, so an owner who disabled a link or let it expire can still expose the full reviewer through the Neon production path. The clone query retains the checks, which makes viewing and cloning inconsistent; restore the same active-share predicate in the direct-read query.

## Supabase subject cascade can split subject and reviewer state

**High — confirmed.** `SupabaseQuizRepository.archiveSubject` first updates every currently active child quiz and then updates the subject; `restoreSubject` first activates the subject and then restores `archived_by_subject` children (`packages/core/src/repositories/SupabaseQuizRepository.ts:264-326`). These are independent Supabase requests. A failure after the first request leaves an active subject whose reviewers remain hidden, or archived reviewers under an active subject; the catch path cannot roll back the already-applied database mutation. The Supabase adapter needs an equivalent transaction/RPC or compensating rollback.

## Per-reviewer data cache bypasses archive and purge invalidation

**High — confirmed.** `getCachedQuiz` stores each reviewer under only `CacheTags.quiz(quizId)` with a five-minute TTL (`apps/web/lib/cached-queries.ts:31-46`), and `GET /api/quizzes/[quizId]` uses it even though the route is marked `noStore` (`apps/web/app/api/quizzes/[quizId]/route.ts:12-15`). The subject archive and restore routes enumerate child reviewers but only revalidate public share tags; New Session clears the process-local repository LRU and list/public tags, not these per-reviewer Next tags (`apps/web/app/api/subjects/[subjectId]/archive/route.ts`, `apps/web/app/api/subjects/[subjectId]/restore/route.ts`, `apps/web/app/api/anonymous/route.ts:56-80`). Consequently an archived reviewer, or a purged reviewer's questions, can remain available through a cached API response to an old identity/device until the entry expires. Add a tag covering all user-owned reviewer details, include it in the detail cache, and revalidate it on subject cascades and purge, or enumerate and invalidate every affected reviewer ID.

## Supabase purge leaves collaborator-link identity metadata

**Medium — confirmed.** The Supabase purge implementation deletes quizzes under owned subjects, owned subjects, `subject_collaborators` rows for the identity, and `subject_views` rows where it was the viewer (`packages/core/src/repositories/SupabaseQuizRepository.ts:668-709`). It never updates `subject_collaborator_links`, even though the schema stores the identity in `used_by` and in the `redeemed_by` array (`sql/schema.sql:119-157`). Links on another user's subject therefore retain the purged Guest ID and redemption metadata. The Neon implementation already removes those array entries and clears `used_by`; apply the same cleanup to Supabase as part of the purge.

## Reset failure can leave a partially purged old identity

**Medium — confirmed.** The reset handler calls the quiz purge, session purge, pairing-ticket cleanup, cache invalidation, and only then creates the replacement cookie (`apps/web/app/api/anonymous/route.ts:49-80`). Delaying rotation until cleanup finishes avoids switching identities before deletion, but the cleanup is not one transaction: any later repository, pairing, or infrastructure error returns a failure while the old signed cookie remains valid and earlier deletions stay committed. Use a single transactional purge where possible, or persist a purge-completion state and make retries complete the same scoped deletion before treating the operation as failed.

## Destructive and public-state behavior is not exercised

**Medium — confirmed.** `packages/core/src/repositories/__tests__/CachedQuizRepository.test.ts` only supplies mocks for the new interface methods; it does not exercise their cascade, ownership, or invalidation behavior. The repository has no added coverage for the Neon/Supabase public-link predicates, manual-versus-subject restore semantics, deletion of questions/sessions/progress/collaborator/view/link/ticket records, or cookie rotation after a failed/successful purge. `git diff main --check` and `pnpm typecheck` pass, but those checks do not validate the failure modes above.
