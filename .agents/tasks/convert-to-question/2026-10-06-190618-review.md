# Deterministic question conversion and scoped authoring undo

This task adds a deterministic reference-substitution converter, routes recognized clipboard pairs through the same prompt builder in manual and add/edit authoring, and adds bounded snapshots for programmatic changes. The scalar predicate now ends in `are often called what?`, and the matrix example follows the intended contextual-opener path without underscores. The authoring flows preserve native paste for unsupported structures and use request tokens for optional SmolLM2 fallback results, while the web typecheck and focused suites pass. Watch for: **confirmed** non-final predicate clauses still produce an ungrammatical `what.` fragment; **confirmed** some later edits do not invalidate pending SmolLM2 results; **confirmed** the modal undo boundary can replace native undo in unrelated editable controls; **confirmed** browser verification is absent and the full suite remains environment-failed.

**Verdict**: NEEDS_CHANGES

## High-level view

The converter is local and regex-based, with explicit escaped term matching and opener/predicate handling. **Confirmed grammar gap:** the final scalar case is correct, but the same predicate rewrite is not sentence-aware when another sentence follows, so a repeated definition can expose `This is known as what.` instead of retaining a grammatical declarative clause or moving the question to the end.

Manual creation and the question modal now share a typed card-construction helper and keep bulk/list/enumeration data on preview or native paths. **Confirmed race gap:** the request counter is not advanced by every user edit path, so a valid but delayed local-AI result can still replace newer state after edits that only clear undo snapshots or change selection state.

Programmatic snapshots are cloned and restored at form boundaries, and the rich-text editor now ignores already-prevented keyboard events. **Confirmed undo-scope gap:** the modal boundary treats every input and contentEditable descendant as an eligible programmatic-undo target whenever any snapshot is pending, which can consume ordinary native undo in explanation and other controls.

**Confirmed verification gap:** the focused pure tests, current web typecheck, and recorded web build do not substitute for a browser session covering paste propagation, native undo ordering, metadata boundaries, and stale-result behavior. The task commit range is source-scope disciplined; the separate current `git diff main` contains unrelated enumeration/review changes and should not be bundled with this task.

### Predicate rewriting and matrix/scalar output

The scalar regression is handled by the naming-predicate pattern: `are often called scalars` becomes `are often called what?`, with the answer slot at the sentence end. The matrix opener path also produces the expected `Here, ... What is this operation called?` shape, and the term is escaped before interpolation with case-insensitive word boundaries.

**Confirmed:** the predicate replacement decides whether to append `?` by checking whether the matched text is at the end of the entire input. If another sentence follows, it retains the source period after replacing the term with `what`; the added test deliberately locks in `This is known as what. this process needs light. What is this operation called?`. That is both grammatically incorrect and inconsistent with the stated requirement that non-final predicate clauses not receive a mid-sentence question fragment. The replacement needs sentence-position handling that preserves a declarative reference for non-final clauses, while retaining the answer-slot question only for the final predicate.

### Paste boundaries, fallback behavior, and async replacement

`createClipboardAuthoringCard` calls the deterministic prompt builder only for `single_pair`, leaves `question_answer` unchanged, and returns `null` for list and enumeration formats. The manual container handler excludes the metadata block through `data-skip-clipboard-intercept`, while explicit rich-question and target-answer handlers handle recognized single cards; the modal has explicit handlers for its question and answer fields. These paths preserve native paste for parser-null and unsupported modal structures, and parser-stripped definitions continue through the core contextual fallback.

**Confirmed:** the request-token protection is incomplete. In `ManualQuizCreator`, `updateExplanation` changes the draft but only calls `clearManualSnapshots`, not `pasteRequestRef.current += 1`; a pending unstructured paste into a question can therefore resolve afterward and call `applyClipboardCard`, replacing the user’s later explanation/question-card state. The modal has analogous un-tokened mutations such as multiple-choice/true-false selection and distractor removal. Every user mutation that can make the pending result stale must invalidate the request, or the async result must carry and compare a complete draft identity/version.

**Confirmed:** no browser harness was available, so event bubbling and native fallback behavior remain unverified despite the explicit boundary code.

### Scoped programmatic snapshots versus native undo

The generic history utility deep-clones bounded snapshots and the focused tests cover clone isolation, restoration, empty history, bounds, and invalidation. Manual undo is narrower: it requires a question-card editable target or a marked import/type/draft control. `RichTextEditor` now returns when an event is already prevented, preventing a captured programmatic undo from being followed by its own `execCommand('undo')`.

**Confirmed:** the modal’s `onKeyDownCapture` condition accepts any descendant `input`, `textarea`, or `[contenteditable="true"]`. After a programmatic paste or type transformation leaves a pending snapshot, Ctrl+Z in the explanation RichTextEditor, enumeration total, answer-term, distractor, or other modal input is consumed by the modal and restores the whole card. The explanation editor is marked to skip clipboard interception, but that marker is not consulted by the undo boundary. The handler must identify only the intended question/answer conversion controls, or clear/route snapshots so ordinary editable controls retain native undo.

The feature records also report a successful web build. **Confirmed coverage gap:** tests are concentrated in pure converter, parser/helper, and snapshot modules; there are no component tests for event propagation, request cancellation, or native undo ordering. The full-suite evidence reports 44/45 files and 396/401 tests before an unrelated `NeonRepositories` worker IPC failure, with a serial retry failing from Node heap exhaustion, so it is not a clean repository-wide pass.
