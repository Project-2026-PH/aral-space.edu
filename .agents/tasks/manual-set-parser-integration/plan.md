# Implementation Plan

## Findings and decisions

- `C:\Users\User\IntelliJ\quiz-creator\apps\web\components\quiz\ManualQuizCreator.tsx` is already a client component and currently uses `parseSmartClipboard` plus async `parseWithSmolLM2` in the prompt and identification-answer paste handlers. Its single-pair and bulk-term call sites currently use `QuizTransformService.phraseIdentificationPrompt`; its question/answer path correctly preserves the supplied question and answer. The manual save POST sends the draft `question_text`, answer option, `typed_answer`/other type, and correct index to `/api/quizzes`, then navigates to `/quizzes/${encodeURIComponent(data.slug || data.id)}`.
- `C:\Users\User\IntelliJ\quiz-creator\apps\web\components\quiz\QuizQuestionFormModal.tsx` currently does not parse pasted text at all. It is a client component used by `C:\Users\User\IntelliJ\quiz-creator\apps\web\components\quiz\QuizOverviewClient.tsx` for both add and edit, and it POSTs/PATCHes directly to the question API routes. `C:\Users\User\IntelliJ\quiz-creator\apps\web\components\quiz\QuizQuestionList.tsx` only renders and deletes questions; it does not need parser changes.
- `C:\Users\User\IntelliJ\quiz-creator\apps\web\lib\convertToQuestion.ts` and its existing test are authoritative: the standalone converter intentionally returns input unchanged for empty/absent terms, performs escaped case-insensitive word-boundary substitution for matching terms, handles `In|With|During|For`, and appends one question suffix only when needed. Do not broaden that contract or add a second suffixing implementation inside components.
- `QuizTransformService.phraseIdentificationPrompt` and `convertToQuestion` are complementary, not interchangeable. Use `convertToQuestion` as the canonical path when a parsed definition contains its answer term, because it supplies the requested contextual substitution and interrogative ending. Retain `phraseIdentificationPrompt` only as a deterministic compatibility fallback when `parseSmartClipboard` or SmolLM2 has removed the term from the definition (notably passive naming definitions) or returns an already-question-form prompt. The fallback must append the standard suffix only if the fallback result does not already end in `?`; structured `question_answer` records bypass both transformations so their question and answer remain verbatim.
- Use a small shared client-safe helper at `C:\Users\User\IntelliJ\quiz-creator\apps\web\lib\clipboardQuestionPrompt.ts` for that decision. This prevents the manual creator and overview modal from diverging or double-transforming. It should trim definition input, preserve a non-empty prompt that already ends in `?`, call `convertToQuestion` first, and otherwise use the existing phrase fallback plus one guarded suffix. Empty definitions/terms return the trimmed/empty input without inventing content.
- The SmolLM2 call remains strictly client-only: invoke `parseWithSmolLM2` only from paste handlers in the two `'use client'` components. Its `null` result, thrown/rejected model load, unsupported browser, or out-of-range input must leave native paste/fallback behavior intact; no API route, server component, core service, or `AiQuizGenerator.tsx` should import it.
- The overview modal is a one-question editor, so it should intercept only `single_pair` and `question_answer` results. It should not silently collapse `bulk_terms`, `question_answers`, or `enumeration_blocks` into one card; those inputs remain native paste text in the modal, while the existing manual creator keeps its pending bulk-import UI.
- Tests are established: root `C:\Users\User\IntelliJ\quiz-creator\vitest.config.ts` aliases `@` to the web app, and focused tests already exist at `C:\Users\User\IntelliJ\quiz-creator\apps\web\lib\__tests__\convertToQuestion.test.ts` and `C:\Users\User\IntelliJ\quiz-creator\apps\web\lib\__tests__\clipboardParser.test.ts`. There is no web component-test dependency or app-level test script, so add unit coverage for the shared prompt helper rather than inventing a component harness.
