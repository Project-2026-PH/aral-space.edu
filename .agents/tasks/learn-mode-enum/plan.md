# Implementation Plan

## Ground-truth decision

The current code has no dedicated enumeration/count field. `packages/types/src/models/QuizQuestion.ts` defines only `question_type` (`multiple_choice | typed_answer`), `options`, `correct_answer`, `answer_text`, and `order_index`; `order_index` is persistence/order metadata, not an enumeration count. The existing manual creator represents an enumeration as a typed-answer row (`apps/web/components/quiz/ManualQuizCreator.tsx`, lines around the submit payload): it filters `options`, stores the item list in `options`, sets `correct_answer` to `0`, and currently stores `answer_text` as `filled.join(', ')`. Therefore the smallest compatible canonical answer-key change is to derive the enumeration count from the persisted non-empty `options` array and store/compare that count as the typed-answer `answer_text` string (for example, `"3"`), while retaining the item choices in `options` for display/export. Do not add a new number field or reinterpret `order_index`.

This addresses the reported empty-choice failure because Learn Mode no longer indexes `options[correct_answer]` for an enumeration answer; it uses the explicit numeric `answer_text`. Existing non-enumeration behavior must remain unchanged: multiple choice uses its selected option/correct index, identification uses its explicit target answer, true/false remains `True`/`False`, and legacy typed-answer rows continue to fall back to `options[correct_answer]` when `answer_text` is absent.

## Assumption to validate during implementation

The phrase “number next to enumeration question” is treated as the number of non-empty enumeration items, because the current schema/model contains no separate count field and the current creator already has the authoritative item list in `options`. If the live fixture demonstrates a separate numeric token embedded in `question_text`, the implementer must document that evidence and adjust the helper to parse that existing representation rather than inventing a new field; add a regression test for the exact fixture.
